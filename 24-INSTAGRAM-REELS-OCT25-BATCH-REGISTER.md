## Veracity and fidelity policy

- **U: User-provided words** — treat the transcript as source material, including recognition errors and cut-off sections.
- **V: Verified project/site** — identified official public presence; does **not** prove license, current capabilities, user adoption, security or suitability.
- **I: Interpretation** — a likely correction or best-practice explanation clearly distinguished from the speaker's exact claim.
- **?: Unresolved** — preserve phonetic name without inventing a URL, full video, missing section, or invented star count.

Numbers on videos can be promotional: “136,000 stars,” “$100M design,” “13,000 leaked selfies,” “1983 baggage ratio,” “zero performance impact,” and “exactly five visual rules” are **not accepted as verified statistics or complete lists** without supporting original evidence.

## Specific corrections retained

1. Stripping braces, semicolons and “code-looking” symbols does **not** stop SQL injection. Use bound parameters.
2. An AI-led security test is supplemental; enforce verified server/database authorization.
3. Network/OSI defenses are layered analogies, not a guarantee that TLS belongs only to conceptual OSI Layer 6.
4. A server firewall should not be altered casually during the only active SSH session.
5. Backfills require idempotent reconciliation; “replace, not add” does **not** apply naively to immutable ledgers.
6. Theme-flipping paywalls and fake loading progress may manipulate users; avoid by default.
7. Small visual icons can use larger invisible touch targets; dimensional units/standards differ.
8. A design skill plus references is useful, but a real rendered/tested product is the acceptance standard.
