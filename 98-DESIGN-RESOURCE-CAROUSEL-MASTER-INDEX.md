## How to apply this directory to real projects

### First choose the problem

- **Visual direction** → 86; extract hierarchy, grouping, content density, contrast and type roles.
- **Real UI behavior/components** → 87; use appropriate semantic component implementations with tests.
- **Motion** → 88; use feedback, spatial context and state changes—no unmotivated spectacle.
- **Consistent agent design memory** → 89 and 95; define project-owned tokens and do/don't rules, review licenses and conflicts before copying external files.
- **Mobile UX** → 90; inspect whole task flows, not desktop screens shrink-wrapped to a phone.
- **Authentic media/assets** → 91, 92, 93; avoid fake testimonials, meaningless imagery and legal/licensing traps.
- **Readable type/color system** → 94; test contrast and actual font use.
- **Working homepage/landing** → 96; strong value proposition, real information and functional CTA.
- **Prelaunch quality** → 97; metrics and lints are subsets of a wider functional/security/accessibility release audit.

### No automatic implementation rule

These entries are **research/reference vocabulary**. They don't authorize copying complete reference sites, installing third-party MCPs/skills, applying gradients or decorative textures by default, replacing authentic avatars with icons, or trusting “performance improved” without actual measurements.

Real app acceptance still comes from [01 — Design/UX](01-DESIGN-UX.md), [02 — Product Quality](02-VIBE-CODED-APP-QUALITY.md), [03 — Production Architecture](03-PRODUCTION-SYSTEM-ARCHITECTURE.md), [37 — Prelaunch](37-WEBSITE-PRELAUNCH-RELEASE-CHECKLIST.md), and the relevant project's explicit needs.
